## Post 1 — trajetória e portfólio

Atender alguém com um problema em um sistema muda a forma como a gente olha para uma interface.

Na minha experiência de suporte ao TecFood/ERP, na Teknisa, lido com solicitações, chamados e consultas SQL. O trabalho pede que eu entenda a situação, organize as informações e acompanhe a demanda com o cliente e as áreas internas.

Tenho levado esse olhar para os meus projetos web. Além de construir a tela, quero entender se a navegação faz sentido e se a pessoa consegue realizar o que precisa.

Curso Análise e Desenvolvimento de Sistemas na Newton Paiva e estou desenvolvendo minha base em HTML, CSS, JavaScript, React e Node.js. Meu portfólio reúne sites, interfaces e experimentos, cada um no seu estágio de desenvolvimento.

Estou buscando oportunidades de estágio e nível júnior em desenvolvimento web e suporte de software.

Meu trabalho está aqui: https://japapaz696.github.io/Repositorio-Curriculo/

## Post 2 — site Verônica

Uma das coisas que observei ao desenvolver o site da psicóloga Verônica Reis Santana foi como a organização do conteúdo influencia a navegação.

O projeto reúne apresentação, especialidades, certificados, depoimentos, blog e uma página de agendamento. Trabalhei a estrutura das páginas, o layout responsivo e os formulários com HTML, CSS e JavaScript. O repositório também tem um backend em Node.js e Express.

Ter a página publicada é uma etapa. Verificar a integração, a privacidade dos dados e o funcionamento do painel administrativo é outra. Ainda estou revisando esses pontos, por isso apresento o projeto pelo que já consigo demonstrar, sem tratar todas as funções como prontas para produção.

Foi uma boa oportunidade para conectar desenvolvimento com uma necessidade de comunicação profissional.

Interface pública: https://site-veronica.onrender.com

## Post 3 — SupportFlow

Minha experiência com suporte me dá várias perguntas para levar a um projeto: como organizar um chamado? Quem pode acessar cada informação? Como acompanhar o que mudou?

Estou trabalhando essas questões no SupportFlow, um projeto próprio de sistema de chamados.

O código reúne uma interface em React e um backend em Node.js/Express, com PostgreSQL, migrations e autenticação. Também há regras de acesso por perfil e testes para partes da aplicação.

O projeto está em desenvolvimento. A interface e os testes ajudam a mostrar o que existe hoje; ainda preciso evoluir a validação integrada e a documentação dos limites da aplicação.

Para mim, o valor desse projeto está em usar uma situação que conheço do atendimento para praticar desenvolvimento de software com mais estrutura.

Código: https://github.com/Japapaz696/SupportFlow

## Recomendações no perfil

Priorizar recomendações reais de pessoas que acompanharam seu trabalho na Teknisa, em atendimento ou em projetos. Cada recomendação deve vir de quem observou a atuação, com exemplos próprios. Não redigir depoimentos fictícios nem solicitar validação de tecnologias que essa pessoa não viu você usar.
